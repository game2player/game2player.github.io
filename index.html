Games

Abstract

Games test multimodal agents on perception, long-horizon planning and precise control. Turning a game into an environment that can score an agent, or train one, is still manual work. Interactive benchmarks integrate a few dozen games by hand or ask a model to judge the play. Offline benchmarks ask questions about screenshots instead of letting models play. Large gameplay corpora pair video with actions but rarely with goals or outcomes that can be checked.

We present Game2Player, an agentic pipeline that turns games from the open web into environments whose tasks are checked against the game's own state. A Builder agent packages each game for offline play with a fixed random seed, exposes its internal state, and writes tasks whose start, progress and success are all computed from that state. A task is only useful if its checks are right, so every task is then played. Coding agents write programmatic policies, VLM agents play from pixels, and the problems they find go back to the Builder for repair.

The same play becomes training data. One runtime records policies, VLM agents and people with the same actions. It logs the game state and the task progress at every step and keeps the reasoning of model players. From xxx web games, Game2Player builds xxx environments with xxx tasks. Policies written by coding agents solve xxx% of these tasks, compared with xxx% for the strongest VLM agent, and a xxxB VLM trained on the collected play improves by xxx on held-out games.

Examples

A task is defined on the game's own state. The Builder writes where it starts, how its progress is measured and when it is done, all as reads of variables in the running game. The three episodes below were played by the Coding Player.

The progress is real and continuous. It is read from the game itself at every step, not estimated from the screen or scored by a model. It rises with every bit of headway the player makes, so even a run that fails shows how far it got.

Players

Every task is played by two kinds of player. The is a coding agent that studies the game and writes a policy in Python. The policy reads the state the Builder exposes and plays in real time, so a task can be played quickly and many times.

The plays from screenshots alone. It looks at the screen, reasons and presses keys, and the game pauses while it thinks. A slow model is therefore judged on its decisions rather than its speed. It shows whether a task can be understood and played from what is on the screen.
